---
name: troubleshooting
description: Diagnose craft-foundry build and game validation failures using structured reports, logs and recorded artifact identities.
---

Read `mch report --run <run-id> --json` and the referenced evidence before changing code. Distinguish a failed assertion from infrastructure errors, unsupported drivers, cancellation, timeouts and zero discovered tests.

For an environment failure, run `mch doctor --json` and check each Java role, wrapper, display environment, configured tool hash and EULA state. For an API/build failure, inspect the selected target's resolved sources and dependencies. For a distribution failure, verify recorded JAR hashes and side placement; compare the helper-free smoke test with detailed tests that include an operation helper.

Preserve the first failed attempt. Reproduction requires the matching revision, working-tree changes and fixed dependencies; the replay command alone does not restore dirty source. Never kill all Java processes or trust a stale PID as ownership. Investigate an ambiguous persistent build lock before removing it.

For acquisition failures, inspect the survival evidence's original/effective coverage, `datapack`, `resourceDiagnostics`, `definitionProcesses` and development diagnostics. Follow `templates/acquisition/README.md` to query the exact resource and runtime process. Check effective byte hashes and visible override stack before attributing a change to Mod source; selected, loaded and disabled pack IDs have different meanings. Source-only/script-removed JSON, runtime-only entries, serializer disagreements, parse failures or missing raw capture require review, not invented routes or provider seeds. Check reload session/generation, conditions, power and custom API execution, then update exact-version definitions and positive/`without` regressions. Preserve incomplete/unknown results and raw field history.

Use exact target resource paths: `yourmod:recipe/press.json` for 1.21.1, `yourmod:recipes/press.json` for 1.20.1. Keep Forge 1.20.1 Gradle/compile/game Java at 17/17/17, Fabric 1.20.1 at 21/17/17, and both 1.21.1 targets at 21/21/21. Inspect resolved APIs; do not reuse 1.21 codecs/components on 1.20 item/NBT/network serializers or broaden other versions.

Both 1.20.1 collectors support bounded loot/block/entity/world observations. Preserve completed manifests, matching session/generation, seeds, tool NBT, player/luck/damage context and chunk/height bounds. Command registration and finite-sample coverage are separate. Finite observations remain partial evidence, never exhaustive absence, sustainability or progression proof; they do not execute actual break/death events or prove arbitrary Java hooks. Preserve raw recipes/network hashes, viewer/world data, original/effective coverage and overlay history. JEI/EMI backing IDs, quantities and display entries do not prove execution or probability. Fabric 1.21.1 finite commands remain unsupported; Forge fluid runtime remains unverified. Validate a new Foundry packed consumer separately from prior Atlas game evidence using `docs/survival.md`; keep Atlas's independent Foundry pin unchanged.

Require `server-persistence` for supported Mods with persistent block entities/state, stored inventory or custom world data. Follow `docs/persistence.md`: seed and verify representative fields, flush/save, cleanly terminate the dedicated process, restart the same disposable world without reseeding, then assert restored values. Reconnect and NBT roundtrips are additional coverage only. Retain both launch logs and the persistence transcript; report missing probes, timeout/forced stop and never-run game coverage accurately.

For a required survival acquisition check, configure `captureRuntime` using `docs/survival.md#fresh-capture-and-built-jar-identity`. Deploy the current Run's distribution and all relevant dependency artifacts, prepare the actual configs/datapacks before launch, and let the runner issue a fresh boot nonce/request and freeze expected inputs before capture. Require collector/API identity contract v1 and inspect actual loaded origins, file/JVM identities, live session/generation, raw manifests and complete companion evidence. Old dumps remain readable for review but cannot pass a required current-build check; changed/missing/tampered/unverifiable identity requires restart/recapture or remains unsupported. Do not attach current hashes to an older dump or promote finite observations to exhaustive acquisition. Keep Atlas's independent bootstrap pin unchanged when testing a packed candidate overlay.
