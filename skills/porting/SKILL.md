---
name: porting
description: Port a Minecraft mod across selected loader/version targets with resolved APIs and human-approved validation scope.
---

Before implementation, agree affected targets, AI checks, human checks and untested scope using the installed package's `templates/validation/README.md` and `docs/development.md`. AI checks build/logic, feature functionality and essential affected persistence; detailed GUI interactions, feel and balance default to humans. Pending human review is not a failed machine test and does not trigger exhaustive automation.

Inspect source and destination separately with `mch inspect --target <id> --json`. Use [Minecraft development basics](../minecraft-development-basics/SKILL.md) for native inventory menus/screens, logical sides, registration, resources and state. Adapt names, constructors and serialization to resolved target sources/mappings; do not copy 1.21 codecs/components into 1.20 item/NBT/network APIs. Resource paths such as 1.21.1 `recipe` and 1.20.1 `recipes` are version-scoped examples.

Share pure Java logic/common behavior where practical; isolate registration, networking and loader APIs. Keep incompatible toolchains in independent build roots. Serialize source-switching tools such as Stonecutter within one working tree; parallel work needs separate copies. Inspect Java requirements: the packaged Forge 1.20.1 fixture uses 17/17/17, Fabric 1.20.1 uses 21/17/17 and both 1.21.1 fixtures use 21/21/21 for Gradle/compile/game.

Keep build dependencies fixed and review runtime metadata independently. Normally allow the development loader/Fabric API version and newer, keep Minecraft's range separate and exclude known incompatibilities with evidence. NeoForge `loaderVersion` is the language loader, not the `neoforge` dependency. Unknown compatibility is not incompatibility; consult the human before narrowing compatibility, refusing startup or restricting player interaction. Optional integrations should degrade locally under normal Mod/config/datapack changes.

Preserve common test IDs/assertions where behavior remains common. Run the approved changed targets and representative compatibility boundaries. Shared networking/resources/adapters require checks on affected targets; unrelated versions and every Modpack combination are not automatic requirements. Missing driver capabilities remain unsupported, never simulated passes. Keep existing required release suites until an explicit scope decision changes them; a passing automated release Run does not complete human criteria.

For affected saved state, choose representative `server-persistence` checks using `docs/persistence.md` when clean save/restart/restoration proof is required. Reconnect/NBT roundtrips alone are insufficient for that claim. Preserve logs, item/data integrity and untested scope. Agreed prerelease/new-save breaks can omit migration; prefer native mechanisms over speculative recovery frameworks.

For agreed acquisition analysis, use `templates/acquisition/README.md` and repository-only `docs/survival.md` for exact Forge/Fabric 1.20.1 and NeoForge/Fabric 1.21.1 adapters. Compare effective resources/override provenance and execution evidence for affected mechanisms, with version-scoped definitions and positive/`without` prerequisite regressions. Raw resources and finite observations do not prove execution, exhaustive absence or progression. Keep unknown hooks explicit; Forge fluid runtime remains unverified. Required current-build checks need fresh `captureRuntime` identity and complete evidence, never an old dump with new hashes. Keep Atlas's independent bootstrap pin unchanged; do not extend its adapter support merely because the Mod is ported.

Read `docs/storage.md` for opt-in storage. Inventory and preview first; apply only exact authorized targets after positively stopped ownership and verified retained evidence. Keep worlds/settings, failed Runs and historical unmarked data. For `after-suite`, reserve across restart gaps, lease every use, attach immutable scoped evidence durably, release all leases and close after final use. Preserve earlier `storageEvidence` references with a 0.1.10-or-later reader. Shared verified assets materialize as independent clone/copy files; logical size is not physical savings. These harness controls do not prescribe restrictions in the Mod.
